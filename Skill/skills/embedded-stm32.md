# STM32 嵌入式开发规范

## 1. 模块化架构

每个硬件/功能模块独立为 `xxx.h` + `xxx.c`。

- **不透明句柄**：头文件只暴露类型声明 `typedef struct XxxHandle *XxxHandle_t`，结构体定义在 .c 中
- **私有数据**：句柄内放运行时状态、依赖的其他句柄；静态不变的参数用 const 配置结构体
- **单一职责**：一个模块只做一类事（如电机驱动、编码器读取、协议解析）
- **依赖注入**：模块需要的其他句柄通过初始化函数传入，不在内部 hardcode

## 2. 命名规范

- **模块前缀**：所有对外符号加 `模块名_`，避免符号冲突（例：`Motor_Init`, `Sensor_Read`）
- **静态函数**：小写蛇形命名，仅文件内可见（`static void update_pwm()`）
- **类型/结构体**：大驼峰（`typedef struct MotorConfig MotorConfig;`）
- **变量/字段**：蛇形命名（`int32_t target_speed;`）
- **宏/常量**：全大写蛇形（`#define MOTOR_PWM_FREQ 20000`）
- 避免与 HAL/OS 命名风格冲突，保持项目内一致

## 3. 新增外设模块流程

1. **引脚规划**：查数据手册/引脚复用表，核验无功能冲突
2. **配置引脚**（工具或寄存器）：输入引脚注意上下拉，输出引脚配置速度/驱动能力
3. **使能外设**：时钟、中断、DMA 等在初始化序列中统一开启
4. **代码生成**：确认 .c/.h 中包含预期的初始化与操作函数，检查默认配置是否合理
5. **独立性**：不依赖全局外设句柄，模块自己管理

## 4. 模块间通信

- **单向依赖**：依赖关系形成树状，禁止循环依赖
- **注入接口**：初始化时传入依赖模块的句柄或回调函数指针
- **模式分发**：若模块有多个工作模式，优先用回调表或函数指针表，模式固定且少时才用 switch
- **解耦**：跨模块数据通过事件/回调通知，不直接操作其他模块内部状态

## 5. 通信实现（UART/SPI/I2C 等）

按场景选择，不强制纯 DMA：

- **大数据量 / 高速**：DMA + 双缓冲，提供完成回调，注意缓存一致性（带 Cache 的 MCU）
- **中速 / 常规交互**：中断驱动，ISR 只做数据搬移和关键标志，快速退出
- **低速 / 调试 / 简单指令**：可接受阻塞方式，以简化逻辑
- **零拷贝**：通信缓冲直接指向应用层数据区，避免 memcpy

## 6. 错误处理与调试

- 公开 API 的指针/句柄参数做非空检查，非法参数返回错误码
- 开发阶段用 `assert()` 捕捉内部逻辑错误（如状态非法），发布版本可替换为错误记录
- 外设操作后提供状态查询接口，不鼓励直接读寄存器
- 硬件异常（超时、应答错误）必须上报，不能静默吞掉

## 7. 最小文档

- 每个 .h 的公开 API 前必须有一行注释说明用途
- 结构体/枚举的每个字段加简要含义注释
- 复杂状态转换或协议加状态图/序列描述
- 统一使用 `/* */` 或 `///` 注释风格，方便生成文档
