## 你是 AI，请严格按以下流程执行

### 身份与目标

你在帮我整理 Obsidian 问题笔记库，路径 `E:\Brain`。
目标：把用户提供的**截图 + 解决方法**，转成结构化 Markdown 笔记，存入 `01-问题库/`，并提交到 Git。

### 第一步：读取规范（必做）

先读这两个文件，了解命名和格式规范：

- `E:\Brain\99-系统\问题库使用说明.md`
- `E:\Brain\99-系统\模板\问题笔记模板.md`

### 第二步：分析输入

从用户提供的材料中提取：

1. **报错原文** —— 图片里的文字，逐字提取，放进代码块
2. **环境信息** —— 操作系统、软件名、版本（用户没说就问，或写"未注明"）
3. **症状** —— 什么操作触发的，现象是什么
4. **原因** —— 为什么会这样（用户没提供就根据报错推断，并标注"推断"）
5. **解决方法** —— 具体步骤，带命令/代码
6. **踩坑记录** —— 用户试过但没用（用户没提供时可留空）

### 第三步：生成笔记

**文件名规则**：`症状描述.md`
- 用**搜索时会输入的关键词**：报错代码、软件名、现象
- 例：`Keil 编译报错 L6200E 重复定义.md`、`STM32 串口打印乱码.md`
- **不要**用科目名（如"嵌入式问题3.md"）
- 中文文件名正常用，不用拼音

**存放位置**：`E:\Brain\01-问题库\<文件名>.md`（扁平放，不建子文件夹）

**图片处理**：
- 用户发来的截图**保存**到 `E:\Brain\01-问题库\_附件\YYYY\` 目录
- 笔记中用 `![[图片文件名]]` 嵌入
- 若图片只有文字且已完整提取，也保留原图备用

**Frontmatter 格式**：
```yaml
---
title: <标题>
date: <YYYY-MM-DD>
tags:
  - <领域标签>
  - <性质标签，可多个>
难度: 简单|中等|困难
解决状态: 已解决|待验证|未解决
环境: <系统 / 软件 / 版本>
---
```

**标签体系**（必须遵守）：

领域标签（一级，至少一个）：
`嵌入式/STM32` `嵌入式/ROS2` `嵌入式/Keil` `考研/高数` `考研/英语`
`工具/Git` `工具/Windows` `工具/Obsidian` `工具/Python` `CV/OpenCV` `CV/图像增强`
`毕设/硬件` `毕设/算法`

性质标签（横切，可多个）：
`编译错误` `运行报错` `配置` `安装` `性能` `踩坑` `待验证`

**正文章节**（严格按模板）：
`# 症状` → `# 原因` → `# 解决方法` → `# 踩坑记录` → `# 相关知识` → `# 参考`

### 第四步：写入并提交

```powershell
cd E:\Brain
git add "01-问题库" 2>&1 | Out-Null
git commit -m "问题库: <笔记标题>" 2>&1
git push origin master 2>&1
```

**注意**：
- 只 `git add` 问题库相关文件，**不要 `git add -A`**（避免误提交 Obsidian 的配置变动）
- commit message 用 `问题库: ` 开头

### 第五步：回报

告知用户：
- 笔记文件路径
- 用了哪些标签
- 是否有需要用户补充的信息（如"原因是我推断的，请确认"）

## 边界与禁忌

### 必须做

- ✅ 报错原文**逐字**提取，不改写
- ✅ 文件名含关键词，便于日后搜索
- ✅ 留出「踩坑记录」章节
- ✅ 写入后提交推送

### 禁止做

- ❌ **不要**改动 `01-问题库/` 之外的文件（尤其 `.obsidian/`、现有科目笔记）
- ❌ **不要**用 `git add -A` 或 `git add .`
- ❌ **不要**新建子文件夹分类（保持扁平）
- ❌ **不要**把笔记写成教程长文 —— 问题笔记要**短、准、可检索**
- ❌ **不要**编造用户没说过的解决步骤

### 环境提醒

- Git 已配置 SSH 走代理（`~/.ssh/config`），push 正常需 5-30 秒
- 若 push 失败报 `Could not read from remote repository`，大概率是代理端口变了（当前 7897），告诉我即可
- vault 已有 51 篇笔记，改动前**不要**碰它们
