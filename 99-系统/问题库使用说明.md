# 问题库使用说明

## 定位

记录**遇到的问题和解决方法**，用于未来忘记时快速回顾。

与 `02-知识笔记`（科目知识）的区别：
- **知识笔记** = 我学到了什么
- **问题库** = 我踩了什么坑、怎么爬出来的

## 目录结构

```
01-问题库/
├── _附件/      图片、截图（按年份分子目录）
├── _收件箱/    待整理的原始材料
└── *.md        问题笔记（全部扁平，不建子文件夹）
```

**为什么扁平**：问题往往跨科目，放子目录会导致"该放哪"的犹豫和"该去哪找"的困难。分类交给标签。

## 命名规范

文件名 = **症状**，不是科目。

| ✅ 好 | ❌ 差 |
|---|---|
| `Keil 编译报错 L6200E 重复定义.md` | `Keil问题.md` |
| `STM32 串口打印乱码.md` | `嵌入式笔记3.md` |
| `Git push 超时.md` | `Git相关.md` |

原则：**未来搜索时会输入什么关键词，文件名就叫什么**。

## 标签体系

### 一级：领域（必填一个）

`嵌入式/STM32` `嵌入式/ROS2` `嵌入式/Keil` `考研/高数` `考研/英语`
`工具/Git` `工具/Windows` `工具/Python` `CV/OpenCV` `CV/图像增强`
`毕设/硬件` `毕设/算法`

### 二级：性质（可多选，横切筛选）

| 标签 | 含义 |
|---|---|
| `编译错误` | 编译/链接失败 |
| `运行报错` | 运行时的错误 |
| `配置` | 环境、配置文件问题 |
| `安装` | 软件/驱动安装 |
| `性能` | 卡顿、超时、资源占用 |
| `踩坑` | 非报错但容易走弯路 |
| `待验证` | 解决方案还没确认有效 |

### 用法示例

```dataview
TABLE date, 解决状态
FROM #编译错误 AND #嵌入式/STM32
SORT date DESC
```

## 检索方式

1. **按症状搜**：`Ctrl+O` 输报错关键词
2. **按标签搜**：`Ctrl+P` → 搜索 `tag:#编译错误`
3. **按领域浏览**：标签面板点 `嵌入式/STM32`
4. **看最近记录**：`Ctrl+P` → 排序方式 → 修改时间

## 录入方式

### 方式 A：对话式（推荐）

直接把**截图 + 解决方法**发给 AI，说明环境，由 AI：
1. 识别图片内容
2. 提取报错原文
3. 按模板成稿
4. 存入 `01-问题库/`，图片存入 `_附件/`
5. 自动 commit + push

### 方式 B：收件箱批量

图片和草稿丢进 `_收件箱/`，攒够后统一说"整理收件箱"。

## 维护习惯

- **趁热记**：问题刚解决时记忆最新鲜，原因和踩坑细节最全
- **踩坑记录别省**：记下"试过但没用"的方法，比记录成功方法更有价值
- **待验证要复查**：带 `待验证` 标签的定期回头看
- **定期合并**：同类问题多了可以合并成一篇综述
