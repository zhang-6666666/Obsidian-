# FishBot ROS 2 通信框架

## 一、核心概念速览

### 类比：微信群聊

| ROS 2 概念 | 类比 | 本项目中的实例 |
|------------|------|---------------|
| **Node（节点）** | 群里的一个人 | `fish_bot_motion_control` |
| **Topic（话题）** | 群聊名称 | `/cmd_vel`、`/odom` |
| **Message（消息）** | 消息格式（文字/语音/图片） | `Twist`、`Odometry` |
| **Publisher（发布者）** | 往群里发消息的人 | 节点在 `/odom` 上发布 |
| **Subscriber（订阅者）** | 群聊的收听者 | 节点订阅 `/cmd_vel` |
| **Executor（执行器）** | 手机的消息推送机制 | 有消息时自动调回调函数 |

```

话题: /cmd_vel (消息类型: Twist)

┌─────────────────────────┐

PC端(teleop) │ linear: {x: 0.1} │ ESP32

┌─────┐ │ angular: {z: 0.0} │ ┌─────┐

│pub │──────→│ │─→│sub │

└─────┘ └─────────────────────────┘ └─────┘

  

话题: /odom (消息类型: Odometry)

┌─────────────────────────┐

PC端(rviz) │ pose: {x:1.2, y:0.3} │ ESP32

┌─────┐ │ twist: {linear:{x:0.1}}│ ┌─────┐

│sub │←──────│ │──│pub │

└─────┘ └─────────────────────────┘ └─────┘

```

**关键点**：发布者和订阅者互不知道对方是谁，它们只通过**话题名**和**消息类型**匹配。就像你在群里发消息，不需要知道谁会看到——只要话题名对，订阅的人自动收到。

## 二、消息（Message）— 通信的数据格式

### 消息是什么

消息就是一个结构体（struct），定义了传输的字段和类型。每个话题有**且仅有一种**消息类型。

### 本项目用到的两种消息

```

geometry_msgs/msg/Twist nav_msgs/msg/Odometry

┌──────────────────┐ ┌──────────────────────┐

│ Vector3 linear │ │ Header header │

│ float64 x ←── 前进速度 │ stamp ←── 时间戳 │

│ float64 y │ │ frame_id ← "odom" │

│ float64 z │ │ child_frame_id │

│ Vector3 angular │ │ Pose pose │

│ float64 z ←── 旋转速度 │ position x,y,z │

└──────────────────┘ │ orientation 四元数 │

│ Twist twist │

│ linear x,y,z │

│ angular x,y,z │

└──────────────────────┘

```

`ros2 interface show geometry_msgs/msg/Twist` 可以查看完整定义。

### 代码中怎么用

```cpp

// 1. 引用头文件（消息结构体定义在里面）

#include <geometry_msgs/msg/twist.h>

#include <nav_msgs/msg/odometry.h>

// 2. 声明变量

geometry_msgs__msg__Twist msg_cmd_vel; // 存储收到的速度指令

nav_msgs__msg__Odometry msg_odom; // 存储要发出的里程计

// 3. 读取消息字段（收到 cmd_vel 时）

target_linear_speed = msg->linear.x * 1000.0f;

// 4. 填充消息字段（发送 odom 时）

msg_odom.pose.pose.position.x = odom.x;

msg_odom.twist.twist.linear.x = odom.linear_speed;

```

## 三、节点（Node）— 机器人在 ROS 2 网络中的身份

### 节点是什么

**节点 = 一个 ROS 2 参与者**。一个机器人可以有多个节点，每个做不同的事。

```

ESP32 上只有一个节点:

fish_bot_motion_control

├── 订阅 /cmd_vel

└── 发布 /odom

```

### 节点包含什么

```

┌── Node: "fish_bot_motion_control" ──┐

│ │

│ subscriber ── /cmd_vel (Twist) │

│ ↓ twist_callback() │

│ │

│ publisher ── /odom (Odometry) │

│ ↑ rcl_publish() │

│ │

│ timer ── 50ms → timer_callback() │

│ │

└── Executor ── spin() 驱动上述一切 ──┘

```

### 创建节点的代码链路

```cpp

// Step 1: 获取默认内存分配器

allocator = rcl_get_default_allocator();

// Step 2: 初始化 ROS 2 支持层（和 Agent 握手）

rclc_support_init(&support, 0, NULL, &allocator);

// Step 3: 创建节点，给它起名

rclc_node_init_default(&node, "fish_bot_motion_control", "", &support);

// Step 4: 就可以在节点上创建 sub/pub/timer 了...

```

## 四、发布与订阅 — 数据的进出

### 4.1 订阅 /cmd_vel：接收速度指令

**初始化**（在 `micro_ros_task` 中执行一次）：

```

rclc_subscription_init_default() 创建订阅者对象

↓

rclc_executor_add_subscription() 注册到执行器

↓

每当有新消息到达，Executor 自动调用 twist_callback()

```

**代码**：

```cpp

// ① 创建订阅者：告诉 ROS 2 "我要订阅 cmd_vel"

rclc_subscription_init_default(

&sub_cmd_vel, // 订阅者对象

&node, // 所属节点

ROSIDL_GET_MSG_TYPE_SUPPORT(geometry_msgs, msg, Twist), // 消息类型

"cmd_vel" // 话题名称

);

// ② 注册到执行器：告诉 Executor "有消息时调 twist_callback"

rclc_executor_add_subscription(

&executor, &sub_cmd_vel, &msg_cmd_vel,

twist_callback, // ← 回调函数

ON_NEW_DATA // ← 只有新数据到达时才触发

);

// ③ 回调函数：收到消息后做什么

void twist_callback(const void *msgin) {

const geometry_msgs__msg__Twist *msg = (const geometry_msgs__msg__Twist *)msgin;

target_linear_speed = msg->linear.x * 1000.0f; // m/s → mm/s

target_angular_speed = msg->angular.z;

// 逆解 → 更新 PID 目标

kinematics.kinematics_inverse(...);

pid_controller[0].update_target(out_left_speed);

pid_controller[1].update_target(out_right_speed);

}

```

### 4.2 发布 /odom：发出里程计数据

**初始化**：

```cpp

// ① 创建发布者：告诉 ROS 2 "我要在 /odom 发布 Odometry 消息"

rclc_publisher_init_best_effort(

&pub_odom,

&node,

ROSIDL_GET_MSG_TYPE_SUPPORT(nav_msgs, msg, Odometry),

"/odom" // 话题名前加 /

);

// ② 创建定时器：每 50ms 触发一次

rclc_timer_init_default(&timer, &support, RCL_MS_TO_NS(50), timer_callback);

rclc_executor_add_timer(&executor, &timer);

```

**发布**（在 `timer_callback` 中每 50ms 执行）：

```cpp

void timer_callback(rcl_timer_t *timer, int64_t last_call_time) {

odom_t odom = kinematics.get_odom(); // 获取最新里程计数据

// 填充消息字段

msg_odom.pose.pose.position.x = odom.x;

msg_odom.twist.twist.linear.x = odom.linear_speed;

// ... 填充其他字段 ...

// 真正发送

rcl_publish(&pub_odom, &msg_odom, NULL);

}

```

## 五、Executor — 消息循环引擎

### 它干什么

Executor = 一个死循环 + 事件调度器。它不断检查"有没有新消息？定时器到时间了吗？"，然后调用对应的回调函数。

```cpp

rclc_executor_spin(&executor); // 阻塞，永不返回

```

等价于：

```

while (true) {

if (sub_cmd_vel 有新消息) → twist_callback()

if (timer 到时间了) → timer_callback()

}

```

### 为什么在 FreeRTOS 独立任务里跑

```

main loop() micro_ros_task()

loop { rclc_executor_spin() { ← 死循环，不退出

PID 控制(10ms) if 有新消息 → twist_callback()

delay(10) if 定时器到 → timer_callback()

} }

```

如果在 `loop()` 里调 `spin()`，整个程序会卡在里面，PID 控制再也执行不了。所以用 `xTaskCreate` 开独立线程，让 ROS 通信和电机控制**物理上并行**。

## 六、完整调用链

### 6.1 初始化流程

```

setup()

│

├─ motor.attachMotor() ← 配置电机 GPIO

├─ encoders[].init() ← 配置编码器 GPIO

├─ pid_controller[].update_pid() ← 设置 PID 参数

├─ kinematics.set_wheel_distance() ← 设置轮距

├─ kinematics.set_motor_param() ← 设置脉冲距离

│

└─ xTaskCreate(micro_ros_task) ← 启动 ROS 2 线程

│

├─ set_microros_wifi_transports() ← 连接 WiFi + UDP

├─ rclc_support_init() ← 初始化 ROS 2 支持

├─ rclc_node_init_default() ← 创建节点

├─ rclc_executor_init() ← 创建执行器

├─ rclc_subscription_init_default() ← 创建 /cmd_vel 订阅

├─ rclc_executor_add_subscription() ← 注册回调

├─ rclc_publisher_init_best_effort() ← 创建 /odom 发布

├─ rclc_timer_init_default() ← 创建 50ms 定时器

├─ rclc_executor_add_timer() ← 注册定时器回调

│

└─ rclc_executor_spin() ← 进入事件循环（永不返回）

```

### 6.2 运行时数据流

```

loop() 每 10ms:

encoders[].getTicks()

→ kinematics.update_motor_speed() // 脉冲→轮速→ odom_update()

→ pid_controller.update(实际轮速) // PID 计算

→ motor.updateMotorSpeed(PID输出) // 控制电机

micro_ros_task 每 50ms:

timer_callback()

→ kinematics.get_odom() // 读里程计结构体

→ 填充 msg_odom 各字段

→ rcl_publish(&pub_odom, ...) // 发出

micro_ros_task 有新消息时:

twist_callback()

→ 读取 msg->linear.x / angular.z

→ kinematics.kinematics_inverse() // 逆解出目标轮速

→ pid_controller.update_target() // 更新 PID 目标

```

## 七、对应表

| 概念 | 代码声明 | 在代码中的体现 |
|------|---------|--------------|
| 节点 | `rcl_node_t node` | `rclc_node_init_default(&node, "fish_bot_motion_control", ...)` |
| 执行器 | `rclc_executor_t executor` | `rclc_executor_spin(&executor)` 阻塞循环 |
| 订阅者 | `rcl_subscription_t sub_cmd_vel` | `rclc_subscription_init_default()` |
| 发布者 | `rcl_publisher_t pub_odom` | `rclc_publisher_init_best_effort()` |
| 定时器 | `rcl_timer_t timer` | `rclc_timer_init_default(..., RCL_MS_TO_NS(50), ...)` |
| 消息变量 | `geometry_msgs__msg__Twist msg_cmd_vel` | `msg_cmd_vel.linear.x` |
| 消息变量 | `nav_msgs__msg__Odometry msg_odom` | `msg_odom.pose.pose.position.x` |
| 订阅回调 | `twist_callback()` | Executor 有消息时自动调用 |
| 定时回调 | `timer_callback()` | Executor 每隔 50ms 自动调用 |
| 发布数据 | `rcl_publish()` | 在 `timer_callback` 内调用 |
